# 플랫폼 입점 브랜드·판매 주체 수집 원칙

## 무신사 같은 플랫폼에서 공개적으로 확인할 수 있는 것

소비자용 플랫폼 화면에서 가장 안정적으로 수집할 수 있는 단위는 보통 **브랜드**다. 반면 `입점 회사`는 법인명, 실제 판매자, 브랜드 소유 회사가 서로 다를 수 있고, 플랫폼이 전체 명단을 공개하지 않는 경우가 많다.

따라서 이 프로젝트는 아래 세 층을 섞지 않는다.

| 층 | 수집 단위 | 공개 확인 방법 | 해석 |
| --- | --- | --- | --- |
| A. 공개 브랜드 로스터 | 화면에 표시된 브랜드 | 카테고리·브랜드관·상품/브랜드 페이지 | 해당 브랜드가 관찰 시점에 플랫폼에서 소비자에게 노출됨 |
| B. 브랜드 운영 회사 | 브랜드를 운영·소유하는 법인 또는 사업부 | 브랜드 공식 사이트, 회사 공식 페이지, 공시 | 회사와 브랜드의 관계가 근거로 확인됨 |
| C. 실제 판매 주체 | 상품 판매 책임 주체 또는 통신판매 신고 주체 | 상품 상세의 판매자 고지, 공식 판매자 정보, 공정위 공개 자료 | 특정 상품·시점의 판매 책임 주체. 브랜드 소유 회사와 같다고 가정하지 않음 |

## 무신사 적용 범위

무신사는 공식 입점 신청에서 사업자등록상 회사명·사업자등록번호·통신판매업 신고번호와 브랜드 정보를 받는다. 그러나 이 정보가 전체 공개 입점사 명단으로 제공되지는 않는다. 회사 사업 소개에는 2025년 기준 `2만 개+ 파트너 브랜드`라는 규모 정보가 있으나, 공개 다운로드 가능한 완전 로스터는 아니다.

그러므로 "무신사 입점사 전수"라는 표현은 사용하지 않는다. 대신 다음처럼 표시한다.

> 공개 페이지에서 확인한 무신사 노출 브랜드 로스터 — 카테고리·검색 범위·관찰일 기준

## 수집 절차

1. 로그인 없이 볼 수 있는 공개 카테고리와 브랜드/상품 페이지에서 브랜드 후보를 수집한다.
2. 동일 브랜드의 중복 표기를 정리하고, 원본 페이지 URL·카테고리·관찰일을 남긴다.
3. 기존 브랜드 데이터와 연결한다. 없으면 브랜드 레코드를 `partially_verified` 또는 `candidate`로 만든다.
4. 공식 브랜드·회사 페이지로 운영 회사 관계를 별도 검증한다.
5. 상품 상세에 판매자 고지가 공개될 때만 실제 판매 주체를 별도 `Seller`로 기록한다.

## 저장 필드

공개 브랜드 로스터에는 최소한 아래를 남긴다.

| 필드 | 설명 |
| --- | --- |
| `platform` | 예: MUSINSA |
| `brand_display_name` | 해당 화면의 브랜드 표기 |
| `brand_page_or_evidence_url` | 확인 페이지 URL |
| `observed_category` | 발견한 카테고리; 전체 취급 품목을 뜻하지 않음 |
| `observed_at` | 확인일 |
| `observation_status` | public_listing_observed / removed_or_unavailable |
| `company_match_status` | not_checked / candidate / verified |

## 안전·품질 원칙

- 로그인, 우회, 자동화 차단 회피 없이 공개 페이지와 공식 공개 자료만 사용한다.
- 사이트 이용 조건·로봇 정책·속도 제한을 준수하고, 대량 수집은 단계별로 멈춰 검토한다.
- 화면의 브랜드 노출은 판매 계약의 법적 증명이나 현재 입점 상태의 영구 보증이 아니다.
- 카테고리별로 보이는 브랜드 수를 합산해 전체 입점 브랜드 수라고 단정하지 않는다.
- 판매자 정보에는 개인사업자 개인정보가 포함될 수 있으므로 공개 저장소에는 개인 식별 정보를 싣지 않는다.
