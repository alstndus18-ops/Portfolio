# 국내 의류 브랜드·쇼핑몰 DB 및 경쟁사 모니터링 기획서

작성일: 2026-10-25 · 작성: 그레이스유 MD (기획MD / 온라인MD)

## 1. 배경과 목적

- 작성자는 그레이스유에 MD로 입사했고, 필요에 따라 기획MD와 온라인MD 업무를 맡는다.
- 목표는 MD 업무와 회사에 실제로 도움이 되는 자료를 만드는 것이다.
- 이를 위해 국내 의류 브랜드와 쇼핑몰의 정보를 모은 DB를 만들고, 그 DB를 바탕으로 경쟁사 운영 현황을 매일 지켜보는 감시형 사이트를 만든다.

## 2. 기존 방식과의 차이

| 구분 | 이전 방식 | 이번 방식 |
| --- | --- | --- |
| 시작점 | 특정 쇼핑몰 URL을 입력 | URL 입력 없음 |
| 경쟁사 찾기 | 입력한 URL을 기준으로 탐색 | 미리 구축한 DB에서 조건에 맞는 곳을 선택 |
| 데이터 | 예시 데이터 | 실제로 확인한 쇼핑몰·브랜드 DB |

## 3. 활용 목적

DB와 모니터링 결과는 아래 업무의 비교 기준과 근거로 쓴다.

- 이벤트·프로모션 기획
- 상품 가격 설정
- 할인율 결정
- 재고 처리

## 4. 전체 구조

```text
① 국내 의류 브랜드·쇼핑몰 DB 구축   ← 지금 단계 (시간이 가장 많이 들어감)
        ↓
② 관심 리스트 선정 (희망 조건·기준에 따라 DB에서 선택)
        ↓
③ AI 에이전트가 관심 리스트만 매일 접속해 정보 수집
   (프로모션, 기획 이벤트, 할인, 운영 정보, 의류 정보)
        ↓
④ 업무에 활용 (벤치마킹, 기준·근거 자료)
```

- ①을 먼저 끝까지 만든다. ③의 수집 대상은 DB 전체가 아니라 ②에서 고른 관심 리스트뿐이다.
- 국내 브랜드를 먼저 만들고, 이후 해외 브랜드로 확장한다. 해외 확장을 대비해 국가·통화 같은 구분 항목을 DB에 넣을 수 있게 둔다.
- 수집한 정보를 화면에 어떻게 보여줄지는 아직 정하지 않았다. 데이터가 어느 정도 모인 뒤 대화하며 하나씩 정한다.
- 이번 기획은 새 웹페이지로 만든다. 기존 포트폴리오 작업물은 지우지 않고 그대로 둔다.

## 5. 1단계: DB 구축 방침

### 5-1. 수집 대상

- 국내 의류 브랜드와 쇼핑몰 전반을 최종 목표로 한다.
- 우선 샘플로 보세 여성 의류 쇼핑몰을 모으고, 이후 일반 브랜드로 넓힌다.
- 범위는 전국이다.

### 5-2. 일반 브랜드와 보세 쇼핑몰은 찾는 기준이 다르다

| 구분 | 일반 브랜드 | 보세 여성 쇼핑몰 |
| --- | --- | --- |
| 주요 출발점 | 공식 브랜드몰, 포트폴리오 페이지, 공시, 플랫폼 입점 목록 | 검색 키워드·광고, 공정위 통신판매 신고 목록, 플랫폼 입점 판매자 |
| 판단 기준 | 회사가 공식 자료로 밝힌 운영 관계가 있는가 | 패션 상품을 실제로 파는, 살아 있는 쇼핑몰인가 |
| 한계 | 대형·중견 위주라 소규모 브랜드가 빠지기 쉬움 | 생기고 사라지는 속도가 빨라 운영 확인을 자주 해야 함 |

### 5-3. 쇼핑몰 포함·제외 기준

- 사이트가 존재하고 접속된다.
- 의류가 주력 상품이다.
- 국내 소비자를 대상으로 한국어로 판매한다.
- 여성 고객이 주 타깃이다. 남녀 공용은 별도로 구분한다.
- **이름으로 된 사이트가 없거나 쇼핑몰이 운영되지 않으면, 공정위나 다른 목록에 있어도 수집하지 않는다.**
- 잡화·화장품만 파는 곳, 접근 제한을 우회해야만 정보를 얻을 수 있는 곳도 수집하지 않는다.
- 도매 전용 몰(소비자가 아닌 판매자 대상)은 제외한다.

### 5-4. 기록 항목 (복잡하게 만들지 않는다)

| 항목 | 설명 |
| --- | --- |
| 쇼핑몰명 | 표시명 |
| 도메인 | 기준 키. 상호는 자주 바뀌므로 도메인으로 식별 |
| 운영사 | 사업자명 (확인되지 않으면 비움) |
| 발견 경로 | 공정위 / 검색 / 플랫폼 / 기존 목록 |
| 확인일 | 마지막으로 사이트를 확인한 날짜 |
| 메모 | 자유 기록 |

진행 상태 항목(후보·보류 등)은 두지 않는다. 확인된 곳만 목록에 남긴다.

### 5-5. 정보를 찾는 곳

- **공정위 통신판매사업자 공개 데이터**: 온라인 판매 신고 사업자의 지역별 목록. 전국 단위로 수집하는 것이 목표다. 개인사업자 정보가 섞여 있으므로 원본은 저장소에 올리지 않고, 상호·도메인 중심으로만 기록한다.
- **DART(전자공시)**: 상장사와 공시 대상 패션 기업을 찾을 때 쓴다.
- **국세청**: 사업자번호 단위의 상태 조회는 가능하지만 업종별 전체 목록은 공개되어 있지 않아, 목록을 만드는 용도로는 쓰기 어렵다.
- **검색엔진, 플랫폼 입점 목록, 공식 브랜드몰**: 사이트를 직접 열어 확인한다.

## 6. 현재까지의 진행 (2026-10-25 기준)

- 보세 여성 의류 쇼핑몰 샘플 100곳을 확보했다.
  - 초기 목록 87곳을 에이전트 브라우저로 하나씩 열어 확인했다.
  - 운영하지 않거나 의류가 아닌 3곳(쉬즈팝: 오픈 전, 골드리아: 주얼리, 딜팡: 골프 용품)을 삭제해 84곳이 되었다.
  - 검색으로 새로 찾아 접속을 확인한 16곳을 추가해 100곳이 되었다.
- 네이버 스마트스토어 1곳(L&D STUDIO)은 스토어 화면이 로그인을 요구해 직접 열어 보지 못했다. 네이버 검색 광고가 집행 중인 것을 확인해 운영 중으로 판단했고, 메모에 한계를 적어 두었다.

## 7. 작업 도구와 방식

- 웹 확인과 검색은 에이전트 브라우저(내장 브라우저)를 먼저 쓴다. 검색엔진 결과 주소를 열어 화면 글자를 읽는 방식이다.
- 에이전트 브라우저에서 열리지 않는 곳(네이버 도메인 등)은 BrowserOS neo로 진행한다.
- 로그인이 필요한 화면은 로그인 정보를 대신 입력하지 않고, 확인 가능한 범위까지만 기록한다.

## 8. 3단계: 일일 모니터링 설계 방향 (DB가 만들어진 뒤)

- 관심 리스트를 만들고, 리스트에 있는 곳만 매일 확인한다.
- 수집 항목 후보: 프로모션, 기획 이벤트, 할인율, 신상품, 가격, 품절 상태.
- 매일 전체를 저장하지 않고 **바뀐 것만 기록**해 DB를 가볍게 유지한다.
- 수집 전에 각 사이트의 이용 약관과 로봇 배제 규칙을 확인한다. 로그인이나 접근 제한을 우회하지 않는다.
- 재고 처리 판단에 쓸 수 있는 신호(품절 수, 할인 시작 시점, 신상품 출시 주기)를 함께 모을 수 있게 한다.

## 9. 위험 요소

| 위험 | 대응 |
| --- | --- |
| 쇼핑몰이 자주 생기고 사라진다 | 모든 레코드에 확인일을 남기고 주기적으로 재확인 |
| 검색 광고에 자주 나오는 곳에 치우칠 수 있다 | 광고와 일반 결과를 구분해 기록, 여러 검색어와 경로를 병행 |
| 공정위 원본의 개인정보 | 원본은 저장소에 올리지 않고 상호·도메인 중심으로만 공개 |
| 사이트 약관·접속 제한 | 약관 확인, 우회 금지, 막히는 곳은 기록하고 넘어감 |
| 로그인이 필요한 화면 | 직접 로그인한 뒤 확인하거나 확인 한계를 메모에 남김 |

## 10. 결정이 필요한 사항

- 속옷 전문몰(예: 감탄)과 애슬레저 브랜드(예: 젝시믹스)를 "의류 쇼핑몰"에 포함할지
- "보세 쇼핑몰"의 경계(자체 제작 비중, 규모 등)를 어디까지로 볼지
- 샘플 100곳 이후 목표 수와 일반 브랜드 수집 시작 시점
- 관심 리스트를 고르는 기준(타깃 연령, 사이즈, 가격대, 카테고리 등)
- 매일 수집한 정보를 어떤 형태(리포트, 변화 알림, 대시보드)로 볼지
