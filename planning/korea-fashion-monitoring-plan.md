# 국내 의류 브랜드·쇼핑몰 DB 및 경쟁사 모니터링 기획서

작성일: 2026-10-25 · 작성: 그레이스유 MD (기획MD / 온라인MD)

## 1. 배경과 목적

- 작성자는 그레이스유에 MD로 입사했고, 필요에 따라 기획MD와 온라인MD 업무를 맡는다.
- 목표는 MD 업무와 회사에 실제로 도움이 되는 자료를 만드는 것이다.
- 이를 위해 국내 의류 브랜드와 쇼핑몰의 정보를 모은 DB를 만들고, 그 DB를 바탕으로 경쟁사 운영 현황을 매일 지켜보는 감시형 사이트를 만든다.

## 2. 기존 방식과의 차이

| 구분 | 이전 방식 | 이번 방식 |
| --- | --- | --- |
| 시작점 | 특정 쇼핑몰 URL을 입력 | URL 입력 없음 |
| 경쟁사 찾기 | 입력한 URL을 기준으로 탐색 | 미리 구축한 DB에서 조건에 맞는 곳을 선택 |
| 데이터 | 예시 데이터 | 실제로 확인한 쇼핑몰·브랜드 DB |

## 3. 활용 목적

DB와 모니터링 결과는 아래 업무의 비교 기준과 근거로 쓴다.

- 이벤트·프로모션 기획
- 상품 가격 설정
- 할인율 결정
- 재고 처리

## 4. 전체 구조

```text
① 국내 의류 브랜드·쇼핑몰 DB 구축   ← 지금 단계 (시간이 가장 많이 들어감)
        ↓
② 관심 리스트 선정 (희망 조건·기준에 따라 DB에서 선택)
        ↓
③ AI 에이전트가 관심 리스트만 매일 접속해 정보 수집
   (프로모션, 기획 이벤트, 할인, 운영 정보, 의류 정보)
        ↓
④ 업무에 활용 (벤치마킹, 기준·근거 자료)
```

- ①을 먼저 끝까지 만든다. ③의 수집 대상은 DB 전체가 아니라 ②에서 고른 관심 리스트뿐이다.
- 국내 브랜드를 먼저 만들고, 이후 해외 브랜드로 확장한다. 해외 확장을 대비해 국가·통화 같은 구분 항목을 DB에 넣을 수 있게 둔다.
- 수집한 정보를 화면에 어떻게 보여줄지는 아직 정하지 않았다. 데이터가 어느 정도 모인 뒤 대화하며 하나씩 정한다.
- 이번 기획은 새 웹페이지로 만든다. 기존 포트폴리오 작업물은 지우지 않고 그대로 둔다.

## 5. 1단계: DB 구축 방침

### 5-1. 수집 대상

- 국내 의류 브랜드와 쇼핑몰 전반을 최종 목표로 한다.
- 우선 샘플로 보세 여성 의류 쇼핑몰을 모으고, 이후 일반 브랜드로 넓힌다.
- 범위는 전국이다.

### 5-2. 일반 브랜드와 보세 쇼핑몰은 찾는 기준이 다르다

| 구분 | 일반 브랜드 | 보세 여성 쇼핑몰 |
| --- | --- | --- |
| 주요 출발점 | 공식 브랜드몰, 포트폴리오 페이지, 공시, 플랫폼 입점 목록 | 검색 키워드·광고, 공정위 통신판매 신고 목록, 플랫폼 입점 판매자 |
| 판단 기준 | 회사가 공식 자료로 밝힌 운영 관계가 있는가 | 패션 상품을 실제로 파는, 살아 있는 쇼핑몰인가 |
| 한계 | 대형·중견 위주라 소규모 브랜드가 빠지기 쉬움 | 생기고 사라지는 속도가 빨라 운영 확인을 자주 해야 함 |

### 5-3. 쇼핑몰 포함·제외 기준

- 사이트가 존재하고 접속된다.
- 의류가 주력 상품이다.
- 국내 소비자를 대상으로 한국어로 판매한다.
- 여성 고객이 주 타깃이다. 남녀 공용은 별도로 구분한다.
- **이름으로 된 사이트가 없거나 쇼핑몰이 운영되지 않으면, 공정위나 다른 목록에 있어도 수집하지 않는다.**
- 잡화·화장품만 파는 곳, 접근 제한을 우회해야만 정보를 얻을 수 있는 곳도 수집하지 않는다.
- 도매 전용 몰(소비자가 아닌 판매자 대상)은 제외한다.

### 5-4. 기록 항목 (복잡하게 만들지 않는다)

| 항목 | 설명 |
| --- | --- |
| 쇼핑몰명 | 표시명 |
| 도메인 | 기준 키. 상호는 자주 바뀌므로 도메인으로 식별 |
| 운영사 | 사업자명 (확인되지 않으면 비움) |
| 발견 경로 | 공정위 / 검색 / 플랫폼 / 기존 목록 |
| 확인일 | 마지막으로 사이트를 확인한 날짜 |
| 메모 | 자유 기록 |

진행 상태 항목(후보·보류 등)은 두지 않는다. 확인된 곳만 목록에 남긴다.

### 5-5. 정보를 찾는 곳

- **공정위 통신판매사업자 공개 데이터**: 온라인 판매 신고 사업자의 지역별 목록. 전국 단위로 수집하는 것이 목표다. 개인사업자 정보가 섞여 있으므로 원본은 저장소에 올리지 않고, 상호·도메인 중심으로만 기록한다.
- **DART(전자공시)**: 상장사와 공시 대상 패션 기업을 찾을 때 쓴다.
- **국세청**: 사업자번호 단위의 상태 조회는 가능하지만 업종별 전체 목록은 공개되어 있지 않아, 목록을 만드는 용도로는 쓰기 어렵다.
- **검색엔진, 플랫폼 입점 목록, 공식 브랜드몰**: 사이트를 직접 열어 확인한다.

### 5-6. 대한민국 패션산업 지도 조사 영역

쇼핑몰 목록을 늘리는 것과 별도로, 대한민국 의류·패션 산업 전체를 한눈에 이해할 수 있는 자료를 만든다. 조사는 아래 7개 영역으로 나누어 계속 축적한다.

| 영역 | 주요 조사 대상 |
| --- | --- |
| 1. 소재·부자재 | 섬유, 원사, 원단, 염색, 단추·지퍼·라벨 등 부자재 업체 |
| 2. 제조·생산 | 봉제공장, 패턴실, 샘플실, OEM·ODM, 국내외 생산 구조 |
| 3. 기업·브랜드 | 패션 대기업·중견기업, 전문 패션기업, 디자이너·독립·라이선스 브랜드 |
| 4. 보세·개인 쇼핑몰 | 사입형, 자체제작형, 혼합형 여성·남성·유니섹스 쇼핑몰 |
| 5. 유통·판매 채널 | 자사몰, 패션 플랫폼, 오픈마켓, 백화점, 아울렛, 편집숍, 홈쇼핑, 오프라인 매장 |
| 6. 서비스·지원 산업 | 물류, 쇼핑몰 솔루션, 결제, 마케팅, 촬영, 미디어, 교육, 협회·정부기관 |
| 7. 시장·소비자·트렌드 | 시장 규모, 소비자 연령·취향·가격대, 인기 카테고리, 구매 채널, 트렌드 변화 |

- 현재 수집 중인 쇼핑몰 DB는 주로 **4. 보세·개인 쇼핑몰**에 해당한다.
- 기업, 브랜드, 쇼핑몰, 판매 채널은 같은 개념이 아니므로 가능한 한 별도 목록으로 관리하고 서로의 관계를 연결한다.
- 국내 구조와 조사 기준을 먼저 안정시킨 뒤 같은 7개 영역을 국가별로 확장한다.
- 해외 확장을 고려해 국가, 지역, 언어, 통화, 공식 사이트와 진출 시장을 추가로 기록할 수 있게 한다.

## 6. 진행 현황

숫자, 최근 작업, 남은 일은 [STATUS.md](../STATUS.md)에서 관리한다.

## 7. 작업 도구와 방식

- 웹 확인과 검색은 에이전트 브라우저(내장 브라우저)를 먼저 쓴다. 검색엔진 결과 주소를 열어 화면 글자를 읽는 방식이다.
- 에이전트 브라우저에서 열리지 않는 곳(네이버 도메인 등)은 BrowserOS neo로 진행한다.
- 로그인이 필요한 화면은 로그인 정보를 대신 입력하지 않고, 확인 가능한 범위까지만 기록한다.

## 8. 3단계: 일일 모니터링 설계 방향 (DB가 만들어진 뒤)

- 관심 리스트를 만들고, 리스트에 있는 곳만 매일 확인한다.
- 수집 항목 후보: 프로모션, 기획 이벤트, 할인율, 신상품, 가격, 품절 상태.
- 매일 전체를 저장하지 않고 **바뀐 것만 기록**해 DB를 가볍게 유지한다.
- 수집 전에 각 사이트의 이용 약관과 로봇 배제 규칙을 확인한다. 로그인이나 접근 제한을 우회하지 않는다.
- 비교군의 옵션 구매 가능 상태·할인 관측 시점·새로 발견한 상품을 모을 수 있게 한다. 경쟁사 판매량·재고 수량으로 해석하지 않는다.

**운영 관점 정리 (2026-10-28):** 상세는 [운영·기획 지표 설계](operating-metrics.md). 4P 관찰 항목에 더해 가격·발주·재고 소진·반품·채널 결정과 실행 검증을 연결했다. 경쟁사 판매량·매출·광고비·전환율은 추정하지 않는다(§10-20). 자사 비공개 데이터로 성과를 검증하는 방안은 제안일 뿐 도입 결정이 아니며, 현재 DB 우선·일일 리포트/알림 보류는 유지한다.

| 결정 | 질문 | 지표 |
| --- | --- | --- |
| 가격 | 우리 가격이 시장에서 어디쯤인가 | 카테고리별 가격 분포(중앙값·가격대), 할인 후 판매가 |
| 할인·프로모션 | 남들은 언제·얼마나·어떻게 하나 | 할인 시작 시점·할인율·형식(타임세일·쿠폰·무료배송 기준)·기간 |
| 상품 기획 | 어떤 아이템이 새로 관측되나 | 신규 관측 수·요일, 아이템 구성. 공식 출시일은 별도 |
| 할인 참고 | 관측 기간에 가격이 어떻게 바뀌나 | 최초 관측→첫 할인 관측 일수, 할인 단계, 세일 카테고리 이동 시점 |
| 벤치마킹 | 어떤 공개 노출 변화가 있나 | 플랫폼 표시 순위, 신규 발견 브랜드, 판매 채널 추가 확인 |

- 최초 상태·성공 관측 시각·변경분·실패 기록을 남겨 날짜별 상태를 복원한다. 처음 발견한 날은 출시일이 아니며 첫 수집에 있던 상품은 기존 상품군으로 분리한다. 실패를 상품 삭제·품절로 처리하지 않는다. 시계열 수집은 보류 해제 후 시작한다.
- 화면 후보: 신상 피드, 경쟁사 비교표, 가격 포지셔닝, 프로모션 캘린더, 브랜드·쇼핑몰 탐색, 주간 요약.
- 우선순위 제안: 기준 브랜드·비교군 선정 → 한 카테고리 가격·구성·정보 누락 비교 → 실행 가설 카드. 일일 수집·시계열 화면·자동 추천은 그 뒤 별도 결정한다.

## 9. 위험 요소

| 위험 | 대응 |
| --- | --- |
| 쇼핑몰이 자주 생기고 사라진다 | 모든 레코드에 확인일을 남기고 주기적으로 재확인 |
| 검색 광고에 자주 나오는 곳에 치우칠 수 있다 | 광고와 일반 결과를 구분해 기록, 여러 검색어와 경로를 병행 |
| 공정위 원본의 개인정보 | 원본은 저장소에 올리지 않고 상호·도메인 중심으로만 공개 |
| 사이트 약관·접속 제한 | 약관 확인, 우회 금지, 막히는 곳은 기록하고 넘어감 |
| 로그인이 필요한 화면 | 직접 로그인한 뒤 확인하거나 확인 한계를 메모에 남김 |

## 10. 결정 사항

결정은 이 절에만 기록한다 (다른 문서에 따로 두지 않는다).

아직 정하지 않은 것:

- "보세 쇼핑몰"의 경계(자체 제작 비중, 규모 등). 3번은 구분 기록만 확정했다.
- 관심 리스트를 고르는 기준(타깃 연령, 사이즈, 가격대, 카테고리 등). 6번.

### 결정 기록 (2026-10-26)

1. 속옷: 이번 DB 범위에서 제외. [14번으로 변경: 포함, 2026-10-27]
2. 애슬레저: 포함. [확정] 애슬레저는 운동 기능과 일상 착용을 합친 의류 분류로 남녀 공용 개념이다.
3. 보세와 일반 브랜드: DB에서 두 유형을 별도로 구분해 기록한다. 법률상 정의는 확인 필요: 보세 의류는 법령상 정의된 용어가 아니라 업계에서 쓰는 말로 보이며, 관세법의 보세구역과는 다른 개념. [확정: 구분 기록 / 법적 정의는 확인 필요]
4. 규모와 확장 순서: 브랜드를 먼저 한다(§11-2·3). 공정위 후보는 강한 후보 511곳까지 확인했고, 나머지는 브랜드 뒤로 미룬다. [변경 확정, 2026-10-26]
5. 결과 형태: 당분간 일일 리포트는 만들지 않는다. 알림도 당분간 하지 않고 DB 수집만 장기간 계속한다. DB가 충분히 쌓인 뒤 대시보드 등 보여 주는 방식을 다시 정한다. [확정: 리포트·알림 보류 / 대시보드는 후속 검토]
6. 관심 리스트 선정 기준: 아직 정하지 않음. [미정]
7. 여성복 수집 범위: 여성 전용 브랜드뿐 아니라 여성 라인이 있는 유니섹스·남녀 동시 전개 브랜드도 포함한다. 다만 여성 전용과 혼합 전개는 분류값으로 구분한다. [확정, 2026-10-26]

2. 일반 브랜드와 패션기업을 별도 엔터티 DB에 추가하고, 기업 → 브랜드 → 자사몰 관계를 공식 근거로 연결한다.
3. 브랜드별 실제 판매 채널 관계(자사몰·플랫폼·백화점·매장)를 개별 근거로 확인해 추가한다.
4. 제조·생산, 소재·부자재, 시장·소비자·트렌드, 서비스·지원 산업으로 조사 범위를 넓힌다.
5. 확인일이 오래된 항목을 주기적으로 재확인하고, 폐업·접속 불가·분류 오류를 정리한다.
6. 데이터가 충분해지면 관심 리스트 기준을 정하고, HTML 대시보드·변화 기록 등 화면 구성을 설계한다.

## 12. 패션산업 지도 추천 조사 순서

7개 영역을 동시에 깊게 조사하지 않는다. 먼저 산업의 흐름과 관계를 이해할 수 있는 대표 사례를 정리한 뒤, 필요한 영역의 전체 DB를 확장한다.

| 순서 | 조사 주제 | 먼저 확인할 내용 | 이후 확장할 DB |
| --- | --- | --- | --- |
| 1 | 유통·판매 채널 | 자사몰, 플랫폼, 백화점, 아울렛, 오픈마켓, 홈쇼핑, 동대문 도매의 역할과 판매 흐름 | 채널별 사업자·입점·매장 목록 |
| 2 | 기업·브랜드 구조 | 기업 → 브랜드 → 자사몰·입점 채널의 관계 | 기업·브랜드·관계 목록 |
| 3 | 보세·개인 쇼핑몰 | 현재 수집 중인 쇼핑몰의 타깃·가격대·운영 방식 | 쇼핑몰 DB 확대 |
| 4 | 제조·생산 | 사입, 자체제작, 국내 봉제, OEM·ODM, 해외 생산의 차이 | 제조·생산 파트너 목록 |
| 5 | 소재·부자재 | 원단·기능성·친환경 소재와 부자재의 역할 | 소재·부자재 업체 목록 |
| 6 | 시장·소비자·트렌드 | 고객층, 가격대, 상품 카테고리, 구매 채널 변화 | 통계·리포트·트렌드 근거 목록 |
| 7 | 서비스·지원 산업 | 물류, 촬영, 마케팅, 솔루션, 결제, 교육·협회 | 지원 사업자·기관 목록 |

- 모든 조사 문서는 `무엇인가 → 누가 참여하는가 → 상품·돈은 어떻게 흐르는가 → MD·디자이너에게 왜 중요한가 → 어떤 DB로 확장할 수 있는가` 순서로 적는다.
- 첫 조사 주제는 **국내 패션 유통·판매 채널 구조**로 한다. 기존 쇼핑몰 DB와 바로 연결되며, 이후 기업·브랜드 관계를 붙일 기준점이 된다.

## 13. 브랜드 찾기 간단 절차 (2026-10-26)

**기본 순서(브랜드 몇 개를 개별로 추가할 때):** (1) 무신사에서 브랜드명 검색 → (2) 브랜드 페이지에서 현재 판매 상품 1개 이상 확인 → (3) 있으면 공식몰에서 동일 브랜드인지만 확인. 이 3단계로 끝낸다. 공식몰은 필수가 아니다. (2)에서 막히면 29CM → W컨셉 순서로 같은 방식을 반복한다. **수천 개를 모을 때는 이 순서가 아니라 노하우 문서의 "목록 받기" 방법을 쓴다.**

**막힘 대응 (최대 1회씩):** 접속 불가·차단·로그인 요구 시 같은 브랜드를 다음 플랫폼에서 한 번 더 확인한다. 그래도 안 되면 DB에는 넣지 않고 다음 브랜드로 한다. 우회·로그인·CAPTCHA는 하지 않는다.

**판단 (플랫폼마다 하나씩, 비율·수식 기준은 쓰지 않는다 §10-13·14):**

| 플랫폼 | 포함 기준 |
| --- | --- |
| 무신사 | 여성 패션 카테고리 목록에 브랜드가 올라와 있으면 포함. 브랜드숍 상품이 0개인 곳은 제외 (§10-13·14) |
| 29CM·EQL 등 | 목록이 300개 상한이거나 의류 아닌 것이 섞이므로, 브랜드숍에서 의류 판매 상품을 1개 이상 확인(상품명·가격)하면 포함. 잡화·침구·펫 위주이거나 확인 상품이 전부 품절이면 제외 |
| 그 밖 | 공식몰 또는 플랫폼 상품 페이지에서 의류 판매를 확인하면 포함 |

여성 전용인지 혼합인지는 포함 여부가 아니라 분류로만 한다(§10-7).

**쇼핑몰(보세 여성 쇼핑몰)을 찾을 때:** 후보 발견(공정위·검색·플랫폼 입점 판매자) → 사이트를 열어 접속·의류 주력·국내 한국어·여성 타깃 확인(§5-3) → §5-4의 6항(쇼핑몰명·도메인·운영사·발견 경로·확인일·메모)만 기록. 도메인이 키다. 확인하지 못하면 목록에 넣지 않는다.

**기록:** 브랜드명, 판매처, 근거 URL 1개(상품 또는 브랜드 페이지), 확인일—네 가지만 남긴다.

브랜드당 페이지 방문은 최대 3회이다. 3회 안에 끝내지 못하면 건너뛴다.

**시행착오 메모:** 검색 결과는 후보를 찾는 용도로만 쓰고, DB 근거는 반드시 공식몰 또는 주요 플랫폼의 실제 상품·브랜드 페이지로 남긴다. 검색 결과가 길거나 공식 URL이 불명확한 후보는 더 파지 않는다.

**빠르게 모으는 방법·시행착오:** [수집 노하우](../research/fashion-commerce-map/docs/11-collection-know-how.md)를 먼저 읽고, 새로 알게 된 것은 그 파일에 추가한다.

층위 A~F, 법인·판매자 관계, 공정위 전수 등 복잡한 단계는 이 절차에 넣지 않고, 필요할 때 별도로 진행한다.

## 14. 월요일 첫 출근 샘플 — 공통 수집 체계

목표: **지금 그레이스유가 비교군과 어떻게 다른지**, **관찰 기간에 무엇이 바뀌었는지**를 같은 웹페이지에서 확인한다. 수집 대상 선정은 §10-23, 이번 체계 적용 결정은 §10-24. 이번 절이 기존 §4·§8·§11의 단계/보류 문구보다 우선한다.

### 대상과 순서

그레이스유 → 쿠메 → 낫띵리튼 → 제이제이지고트 → 오르. 비교 기준인 그레이스유에서 방식과 화면을 잡고, 이후 같은 항목을 적용한다. 수집 대상은 공식몰 4곳과 제이제이지고트 공식 그룹몰 브랜드관 1곳이며, 해당 브랜드 여성 의류만 포함한다. 남성·키즈·가방·신발·소품은 이번 의류 통계에서 제외한다. 여성/공용 표기가 모호하면 원문을 보관하고 분류를 확정하기 전 집계에서 뺀다.

| 브랜드 | 고정 판매처 | 비교 역할 |
|---|---|---|
| 그레이스유 | graceu.co.kr | 기준 브랜드 |
| 쿠메 | kume-studio.co.kr 여성 메뉴 | 페미닌 일상복·니트 |
| 낫띵리튼 | nothing-written.com 여성 의류 메뉴 | 클래식 일상복·비슷한 예산 |
| 제이제이지고트 | pc.babathe.com/bnd/jjjigott 브랜드관 | 원피스·블라우스·할인 운영 |
| 오르 | orr.store | 테일러링·소재·드레시한 상의 |

29CM/W컨셉 기존 자료는 별도 채널 참고 자료로 보존한다. 월요일 1차 결과물의 일일 추적은 위 5개 판매처에 집중한다. 판매처가 달라지면 별도 시계열이며, 쿠폰 가격과 공식몰 표시가를 이어 붙이지 않는다.

### 무엇을 얼마나 모으나

| 묶음 | 범위·수량 | 수집 항목 | 갱신 |
|---|---|---|---|
| 브랜드 기본 | 5곳 각 1건 | 이름·공식 URL·소개 요약·비교 이유·의류 메뉴 구조·배송비/무료배송 기준 | 처음 1회, 변경 확인 시 수정 |
| 상품 기본 | 지정 판매처의 여성 의류 목록에서 접근 가능한 전 상품. 품절 노출·이월/세일 상품도 보관 | 판매처 상품 ID·URL·이름·원본/공통 카테고리·대표 이미지 URL·표시 정가·화면 판매가·할인 표시·명시된 품절/예약 상태·시즌/이월 표기·확인 시각 | 매일 |
| BEST·NEW 노출 | 브랜드별 BEST 상단 20개 + NEW 상단 20개 이내, 각 목록별 원래 순서 유지 | 목록 URL·정렬명·상품 ID·노출 위치·명시적 순위·NEW 배지 | 매일 |
| 행사 | 메인 및 진행 중 행사 목록에서 확인 가능한 공개 행사 | 행사명·URL·혜택 원문·대상/최소금액 조건·명시된 시작/종료 시각 | 매일 |
| 상세 비교 표본 | 브랜드당 최대 12개, 5곳 합계 최대 60개 | 주원단·혼용률(겉감/안감 구분)·원단 형태/가공·핏/기장/넥/소매·색상/사이즈 옵션·실측·명시된 제조국·상품 설명 | 최초 및 해당 표본의 설명/옵션 변경 시 |

전체 상품 수는 처음 목록을 읽은 뒤 확정한다. 임의로 100개/5페이지에서 끊고 전체라고 부르지 않는다. 페이지/커서의 종료 여부와 사이트 표시 개수를 확인하고, 제한·실패가 있으면 실제 확보 건수와 누락 범위를 표시한다. 상세 정보가 기본 목록에 함께 있으면 표본 밖에서도 보존할 수 있지만, 모든 상세 이미지 OCR을 매일 반복하지 않는다.

BEST/NEW 메뉴가 없으면 `미제공`, 접근 실패면 `확인 실패`로 구분한다. 일반 상품 목록 1번을 BEST 1위로 대체하지 않는다. 브랜드가 순위를 표시하지 않으면 ‘BEST 영역 노출 순서’로 기록한다. NEW 영역 상위 20개와 별개로, 전체 목록 ID 비교로 처음 발견한 상품도 찾는다.

### 카테고리와 상세 표본 선택

- 공통 분류 6개: **상의(니트 제외) / 니트·가디건 / 원피스 / 아우터 / 스커트 / 팬츠**. 세트는 별도 분류하여 단품과 가격 비교하지 않는다. 블라우스·셔츠·티셔츠 등 세부 종류와 원본 메뉴명도 남긴다.
- 상품 한 개의 주 분류는 하나로 고정한다. 예: 니트 원피스는 원피스, 소재/형태는 니트. 여러 메뉴에 나와도 중복 집계하지 않는다. 분류 변경은 가격 변화와 구분한다.
- 표본은 카테고리별 2개를 기본으로 한다. 그레이스유에서 BEST 노출 상품 1개와 다른 가격/형태의 현행 상품 1개를 선정한다. BEST가 없으면 같은 카테고리 중간 가격대 상품을 고르고 선정 이유를 적는다.
- 비교 브랜드는 그레이스유 표본과 종류·착용 용도·시즌·기장/핏·소재·화면 판매가를 함께 보고 가까운 것을 찾는다. 조건이 안 맞으면 비교 가능 범위와 차이를 적고, 억지로 2개를 채우지 않는다. 카테고리가 없는 브랜드는 0개로 남긴다.
- 최종 상세 비교는 그레이스유 기준 최대 12개 묶음으로 보여 준다. 비교쌍별 ‘겹치는 점·다른 점·가격 차이’를 짧게 기록하며, 유사도를 정밀 점수처럼 표시하지 않는다.
- 소재는 상품명·상세 텍스트·설명 이미지에 적힌 글자에서만 취득한다. 옷 사진 외형으로 혼용률/원단을 추측하지 않는다. 이미지 글자 위치·판독 원문은 최소한의 근거로 남기고, 불명확한 값은 비워 둔다. 기본값은 null, 0%/0원으로 채우지 않는다.

### 날짜·가격·상품을 비교하는 기준

1. **시각:** `observed_at`은 실제 확인한 한국 시각(UTC+09:00). 공개 등록일/출시일은 출처와 날짜 의미가 명시된 경우만 별도 기록한다. `first_seen_at`은 이 조사에서 첫 발견한 날이며 등록일이 아니다. 첫 수집에 있던 상품을 모두 신상으로 표시하지 않는다.
2. **가격:** 원화 정수로 저장한다. `regular_price`는 사이트가 표시한 정가, `sale_price`는 누구나 볼 수 있는 판매가다. 정가가 없으면 비워 둔다. 할인율은 두 값이 유효할 때 `(정가-판매가)/정가×100`으로 계산하고 사이트 표시 할인율도 따로 보존한다. 할인율 변화는 %p, 가격 변화는 원과 %로 보여 준다. 쿠폰·회원·결제수단 조건부 혜택은 별도 설명으로 둔다.
3. **상품 식별:** 같은 판매처 상품 ID/품번을 우선한다. 상품명이 같다는 이유만으로 합치지 않는다. 색상별 페이지는 원본 ID를 유지하고, 동일 모델이라는 근거가 있는 경우만 `model_id`로 묶는다. 미확정은 별도 상품으로 두고 중복 가능성을 표시한다. 색/사이즈별 가격 차이는 범위로 보여 주며 가상의 평균 구매가를 만들지 않는다.
4. **상태:** 확인된 판매 가능/품절/예약 표시는 원문과 함께 남긴다. 목록에서 상태가 안 읽히면 ‘알 수 없음’이다. 전날 상품이 안 보이면 ‘목록 미노출’이며 삭제/판매 완료로 단정하지 않는다. 실패한 수집은 가격 불변/품절로 처리하지 않는다.
5. **변화:** 같은 판매처·같은 상품/옵션·같은 가격 조건끼리 비교한다. 실제 변화 시점은 두 확인 시각 사이로 표현한다. 하루 여러 번 확인했다면 모든 실행을 보존하고, 일별 대표 실행은 해당 브랜드에서 정해진 시간대의 마지막 정상 완료 실행으로 선택해 화면에 시각을 보여 준다. 부분 수집은 일별 전체 대표값을 대체하지 않는다.

### 저장 형식과 화면용 산출물

수집 원본은 **JSON**, 사람이 가져갈 표는 **UTF-8 CSV(엑셀용 BOM 포함)**, 보는 화면은 **HTML**로 만든다. CSV·화면은 원본에서 생성하며 별도로 수동 수정하지 않는다. 다음 구조는 구현 규격이며 아직 신규 수집 파일을 만들었다는 뜻은 아니다. 저장 위치는 기존 `research/graceyou-comparison/`를 사용한다.

| 자료 | 키와 주요 필드 | 저장 방식 |
|---|---|---|
| 브랜드·수집 범위 | `brand_id, channel_id, source_urls, category_mapping, selection_reason` | 설정 JSON. DB 기존 ID가 있으면 연결 |
| 상품 기준 정보 | `channel_id + product_id`, `model_id, name, url, image_url, category_raw, category, subtype, first_seen_at, published_at, published_date_kind` | 상품 마스터 JSON, 수정 이력은 실행 원본으로 복원 |
| 매일 상품값 | `run_id + channel_id + product_id`, `observed_at, regular_price, sale_price, displayed_discount_pct, availability, season_label` | `snapshots/monitor/<brand_id>/<YYYY-MM-DD>/<run_id>.json`. 기존 날짜 파일 덮어쓰기 금지 |
| BEST/NEW·행사 | `run_id, list_url, list_kind, sort, product_id, position, explicit_rank` 또는 행사명·조건·기간 | 같은 실행 JSON의 `placements`, `promotions` 배열 |
| 상세·비교 표본 | 상품 키·필드별 명시값·근거 URL/원문·확인 시각, 비교쌍 ID·선정 이유·차이 | 상세 JSON과 비교 연결 JSON. 재확인 실패 시 기존 값의 확인일을 바꾸지 않음 |
| 실행 결과 | `run_id, started_at, finished_at, status, expected_count, fetched_count, failed_urls, end_reached, scope` | 같은 실행 JSON의 메타데이터. `complete/partial/failed`, 표시 총수가 없으면 `expected_count=null` |
| 다운로드·화면 | 상품별 일자 기록, 변동 목록, 카테고리 가격표, 상세 비교표 | 원본에서 CSV 및 화면용 JSON 생성. HTML은 인터넷 없이도 핵심 표를 볼 수 있게 준비 |

상품 수는 페이지 ID 수와 모델 수를 구분한다. 카테고리 가격 비교는 모델당 1표로 계산하며, 색상 가격이 다르면 확인된 최저 화면 판매가를 대표로 쓰고 가격 범위도 함께 표시한다. 조건이 없는 균일 모델가는 그대로 쓴다. **이는 비교용 진입 가격이며 실결제가 아니다.** 기존 비교표의 색상 가격 중간값과 계산 기준이 달라 재집계한 표끼리만 비교한다. 품절 여부 미확인은 별도 건수로 표시한다.

### 웹페이지에서 보여 줄 것

- **브랜드 비교:** 소개·비교 이유·카테고리 상품 구성·BEST 노출·공개 행사. ‘주력’은 상품 수 비중과 메인/BEST 노출 근거를 나란히 보여 주며 매출 비중으로 표현하지 않는다.
- **카테고리 가격:** 상품 수·중앙값·중간 50% 가격 구간·할인 표시 비중. 정가/판매가, 전체/판매 가능 확인 상품, 확인 가능한 현행/이월 표시 필터를 둔다. 시즌 불명은 별도 표시하며 임의로 현행 상품에 넣지 않는다.
- **비슷한 상품:** 사진·원본 링크·판매가·소재·형태·실측과 공통점/차이. 수집/분류가 부족한 비교는 그 사실을 표시한다.
- **날짜별 변화:** 상품별 전후 가격·할인율·BEST 진입/이탈·최초 발견·품절 표시 변화. BEST 상위 20개 이탈은 전체 BEST 제외라는 뜻이 아니다. 상품 가격 변화와 상품 구성 변화에 따른 중앙값 변화를 구별한다.
- 화면마다 수집일시·실제 확보 건수·미수집 범위를 보여 준다. 실패일은 선 그래프를 이어 붙이거나 0으로 표시하지 않는다. 성공한 비교에서 변화가 없으면 ‘변화 없음’, 비교 자체가 불가능하면 ‘비교 불가’다.

### 10월 29일 파일럿으로 보완한 공통 규칙

5개 브랜드 목록 및 상세 각 1개(총 5개 상품), 일부 BEST/NEW·페이지 이동·접힌 설명·옵션을 실사했다. [실사 결과와 원본](../research/graceyou-comparison/pilot/README.md)을 따른다. 전체 수집 또는 모든 예외 검증 완료가 아니다. 다음 보완 규칙은 위의 간략 필드 설명보다 우선한다.

- 브랜드별 수집 방법은 달라도 출력 의미는 같다: **사이트별 추출 → 공통 필드 변환 → 공통 검증**. 새 어댑터가 기존 수집 파일을 덮어쓰지 않는다.
- 가격은 `price_observations[{value, kind, raw, conditions, source_url, observed_at}]`로 분리한다. `kind=regular/public_sale/conditional/unknown`. JJ지고트 실사에서 목록 390,040원은 쿠폰가, 상세 기본 판매가는 419,400원이었다. 목록 숫자를 무조건 sale_price에 넣지 않는다. 할인 표시에는 `discount_basis`도 남긴다. 오르 ‘할인가’ 문구만으로 정가·할인율을 만들지 않는다.
- 필드 상태는 `observed/not_checked/not_provided/failed/conflict`. null과 함께 상태를 보존한다. 접힌 설명·하단 이미지 미확인 상태는 not_checked이며 미제공이 아니다.
- 옵션은 `variant_id`와 색상·사이즈 선택 관계를 보존한다. 색상 선택 전 빈 사이즈 목록을 품절로 보지 않는다. 상품 전체 판매상태와 옵션별 상태, 출고 안내를 분리한다.
- 원본 카테고리는 복수 저장, 공통 주분류는 하나. 니트 메뉴의 원피스·팬츠는 각각 원피스·팬츠로 분류한다. 여성 메뉴의 명시적 UNISEX는 별도 태그로 포함 가능하며 여성전용 건수와 구분한다. 미확정 모델 묶음이 있으면 모델 수/통계라고 단정하지 않고 페이지 기준과 구분해 확정률을 표시한다.
- 소재는 `materials[{component, fiber, percent, raw}]`로 겉감/안감/충전재/내피를 나눈다. 치수 단면/둘레·단위·사이즈 원문을 보존한다. 판매자 촉감 설명은 객관적 소재 판정과 구분한다.
- BEST/NEW는 영역·정렬·원본 위치를 함께 기록한다. 오르 BEST의 신상품순처럼 BEST 영역과 판매순위는 다르다. 의류만 필터링해도 원본 위치를 다시 매기지 않는다. 미확인 전용 메뉴를 시즌/리스탁/전몰 BEST로 대체하지 않는다.
- 제조연월·출고예정일·이미지 파일 경로의 연월은 등록일로 사용하지 않는다. 카테고리별 범위/종료를 기록하고 동일 ID 반복을 무조건 정상 종료로 보지 않는다. 부분 실행으로도 동일 상품·동일 조건 변화는 확인할 수 있으나 전체 분포 변화에 사용하지 않는다.
- 본격 수집 전 브랜드별 존재하는 정상/할인/품절/쿠폰/옵션/세트 유형을 표본 대조한다. 이번 1개 상세 표본만으로 모두 통과했다고 보지 않는다. 예약과 전체 수집기는 아직 미구현이다.

### 기존 구현의 보완 목록

- 기존 `tools/run_daily.cmd`는 쉬즈미스 포함·오르 제외이고 전 브랜드 실행 방식이다. 브랜드 선택 실행과 최신 후보 설정을 먼저 연결해야 한다.
- 기존 날짜 파일은 재실행 시 덮어쓰므로 실행 시각별 보존이 필요하다. 날짜만 있는 과거 파일의 시각을 새로 지어내지 않는다.
- 쿠메 기존 `snapshots/official/kume/2026-10-29.json` 표본에는 이름이 ‘상품명’으로 저장돼 있다. 원본을 보존하고 해당 수집 경로의 상품명 추출을 먼저 보완한다. 이 한계가 다른 상의 상세 원본에도 똑같이 있다는 뜻은 아니다.
- 기존 `pos`는 합친 일반 목록의 순서이므로 BEST 순위로 쓸 수 없다. BEST/NEW 원본 목록을 별도로 읽어야 한다.
- 기존 차이 도구의 ‘신상/삭제’ 문구는 최초 발견/목록 미노출로 보정하고, 실패·부분 수집을 비교에서 구분해야 한다.
- 기존 상세 자동 수집은 상의 중심이며 오르·나머지 의류 카테고리·새 상세 표본 수집은 추가 구현이 필요하다. 기존 기준선은 품질/범위가 확인된 항목만 재사용한다.
- 해당 조사 폴더 README에 다른 작업자의 수집 담당 기록이 있다. 이번 요청으로 체계는 이 기획서에 먼저 확정하고, 후속 구현 시 현재 Git 변경·담당 기록을 다시 확인해 겹치는 파일 편집을 피한다.
