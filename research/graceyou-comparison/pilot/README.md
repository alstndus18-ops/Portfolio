# 5개 브랜드 공통 수집 규격 실사

2026-10-29, 한국 시각. 각 브랜드 목록 1곳과 상세 1개(총 5개 상품)를 실제 브라우저로 확인하고, 일부 BEST/NEW·페이지 이동·옵션·접힌 설명을 추가 확인했다. 원본은 `2026-10-29/*.json`이며 파일마다 확인 시각과 실제 URL이 있다. **전체 상품 수집이나 모든 예외 검증을 완료한 것은 아니다.** 기존 수집 파일은 수정하지 않았다.

## 결론

저장 형식과 비교 기준은 통일할 수 있다. 다만 같은 CSS나 목록의 첫 가격을 모든 브랜드에 적용하면 틀린다. **브랜드별 읽는 방법 → 공통 의미로 변환 → 공통 검증**의 3단계로 진행한다. 현재 파일은 수동 검토한 파일럿이며 운영 수집기가 아니다.

## 목록·BEST/NEW 실사

- 그레이스유: Tops에 니트 포함, NEW ARRIVAL 별도 메뉴를 실제 확인했다. 확인한 메뉴에서 BEST는 찾지 못했다. 홈 전체 탐색 전까지 `not_checked`이며 미제공 확정 아님.
- 쿠메: WOMEN BEST 19개 노출을 확인했다. 명시적 순위는 확인하지 못했으므로 위치만 저장한다. 여성 TOP에도 UNISEX가 존재한다. 신상품 정렬과 별도 시즌 컬렉션은 NEW 메뉴와 의미가 다르다.
- 낫띵리튼: Tops 1·2페이지 각 12개 노출, 다른 상품으로 이동함을 확인했다. Restock/26 Fall이 보이지만 이를 BEST 또는 정확한 등록일로 치환하지 않는다. BEST/NEW 전용 경로는 이번에 확정하지 않았다.
- JJ지고트: 전체 브랜드관 표시 total 485, 최초 로딩은 상품 카드 50개. 이것은 의류 전체 확정 수가 아니다. 기본 MD 추천순, 최신순·판매순 등 별도 정렬이 있다. MOST LOVED와 전몰 베스트는 범위가 다르므로 브랜드·정렬·품절제외 상태를 고정해야 한다. 전체 스크롤 종료와 브랜드 전용 BEST는 후속 확인 대상.
- 오르: 니트 목록 첫 12개와 더 보기, 별도 BEST SELLER 및 NEW IN을 확인했다. BEST SELLER도 화면 정렬은 ‘신상품순’이며 신발이 섞인다. 이것은 판매순위가 아니다. 니트 메뉴에 원피스/팬츠도 포함되므로 단순 메뉴명 매핑 불가. 더 보기 끝까지 확인하지 않았으므로 전체 건수는 미확정.

## 반드시 보완할 공통 설계

1. **가격 문맥:** `price_observations[]`에 원문·값·종류(`regular/public_sale/conditional/unknown`)·조건·목록/상세·시각을 둔다. 확인된 public_sale만 비교용 sale_price로 사용. 표시 할인율에도 적용 기준을 붙인다. 목록/상세가 다르더라도 쿠폰 차이면 가격 변동 이벤트가 아니다.
2. **값의 상태:** 필드마다 `observed/not_checked/not_provided/failed/conflict` 중 하나와 근거를 둔다. null 하나로 다 뭉개지 않는다. 펼치기/하단/설명 이미지까지 확인하지 않았다면 not_provided 금지.
3. **상품·옵션:** `product_id` 아래 `variant_id`(없으면 선택값으로 만든 로컬 옵션 키와 생성 방식)를 두고 색상 선택→사이즈 로딩 순서를 따른다. 옵션의 단순 곱으로 실제 조합 수·재고를 만들지 않는다. 버튼 존재만으로 모든 옵션 판매 가능으로 확정하지 않는다.
4. **카테고리:** 원본 메뉴는 다대다로 보존하되 공통 주분류는 한 개. 니트 원피스=원피스, 니트 팬츠=팬츠. 상품 설명으로 구분 불가능하면 미분류. 여성 메뉴의 명시적 공용 제품은 `audience=unisex`로 포함 가능하되 여성전용 필터와 건수는 분리한다. 남성 메뉴 단독 상품 제외.
5. **소재·치수:** `materials[{component, fiber, percent, raw}]`. 겉감·안감·충전재·내피 혼합 금지. 합계 검증도 같은 부위 내에서만 한다. 치수는 cm와 단면/둘레를 따로 기록하고 임의 변환하지 않는다. JJ의 가슴둘레98과 쿠메 Chest58.5를 같은 치수로 바로 비교하지 않는다.
6. **노출:** BEST/NEW 영역 여부, 현재 정렬, 원래 전체 노출 위치를 별도로 저장. 신발 등을 제외해도 원본 위치는 다시 매기지 않는다. ‘의류만 재정렬한 표시 순서’가 필요하면 별도 필드. BEST는 매출 순위/판매량의 대용값이 아니다.
7. **날짜:** 제조연월·출고 예정·리스탁 차수·이미지 경로의 연월·첫 발견일은 출시일과 별개. 공개 등록일이 없으면 빈 값 유지.
8. **범위/실패:** 카테고리마다 표시 수·관측 ID 수·페이지/커서·마지막 상품·종료 사유를 저장. 같은 ID 반복은 종료 성공이 아니라 페이지 이동 실패 가능성. 부분 성공은 상품별 동일 조건 가격 비교에만 쓰고 전체 중앙값 변화에는 사용하지 않는다.
9. **모델 집계:** 모델 관계가 미확정인 상품은 임의 통합하지 않는다. 모델 기준 통계를 내면 묶음 확정률을 같이 표시. 미확정이 섞였으면 ‘모델 수’라고 단정하지 말고 관측 페이지 기준 통계와 분리한다.

## 다음 단계의 작은 합격선

브랜드별 수집기를 연결할 때 정상·할인·품절·조건부 가격·옵션·세트 중 **해당 브랜드에 실제 존재하는 유형**을 각 1개 이상 대조한다. 목록 2회 로딩의 ID 변화, BEST/NEW 범위, 소재 텍스트/이미지 중 실제 제공 경로를 확인한다. 이번 5개 표본만으로 모든 예외 통과 처리하지 않는다. 쿠폰가 분리와 펼친 섹션 읽기를 먼저 적용하고, 그레이스유부터 기준선 수집한다.

`probe.py`는 지정 URL의 공개 화면 텍스트·링크·옵션·설명 이미지 주소·상품 구조화 데이터를 실행별 JSON으로 남기는 보조 도구다. `--current`는 펼치기/옵션 조작 후 상태를 보존한다. 사이트별 자동 정규화, 전체 수집, 예약 실행은 구현하지 않았다.
