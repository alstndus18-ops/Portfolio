# 05. 한국 전수 조사 운영 모델

## 목표를 정확히 정의한다

이 프로젝트의 목표는 "유명한 쇼핑몰 목록"이 아니라, 기준일을 붙여 **한국 패션 커머스에서 공개적으로 식별 가능한 모든 대상**을 최대한 빠짐없이 수집·연결·검증하는 것이다.

여기서 "모든"은 영구적으로 끝난 숫자가 아니다. 신규 사업자, 상호 변경, 휴·폐업, 브랜드 론칭과 플랫폼 입점이 계속 생기므로, 아래 네 가지를 항상 함께 관리해야 한다.

1. 포함 기준
2. 수집 모수(어떤 공식 목록을 출발점으로 삼는가)
3. 마지막 수집·검증 시점
4. 아직 분류하지 못한 항목과 누락 사유

## 국내 수집 대상의 층위

| 층위 | 실제로 모으는 대상 | 모수·주 출처 | "전수" 주장 가능 여부 |
| --- | --- | --- | --- |
| A. 통신판매 신고 사업자 | 온라인 판매 신고가 공개된 사업자 | 공정거래위원회 통신판매사업자 전체 데이터 | 해당 공개 데이터의 기준일·필드 범위 안에서만 가능 |
| B. 공시 대상 패션 기업 | 상장사·공시 대상 주요 비상장사 | DART | DART 공시 대상 범위 안에서만 가능 |
| C. 패션 브랜드·D2C | 독립 브랜드와 자사몰 | 공식 사이트·사업자 정보·브랜드 카탈로그 | 완전 전수 불가. 후보·확인 상태를 분리 |
| D. 플랫폼·전문몰·편집숍 | 다수 브랜드 또는 판매자를 연결하는 서비스 | 공식 서비스·사업자 정보 | 기준 목록을 공개한 범위 안에서 관리 |
| E. 리세일·중고·해외구매대행 | 리세일 플랫폼, 중고 패션 채널, 전문 판매자 | 공식 서비스·공개 판매자 정보 | 채널별 범위를 명시 |
| F. 오프라인 기반 유통 | 백화점·아울렛·브랜드 매장 등 | 회사 공식 정보·공시 | 온라인 채널과 연결되는 범위부터 시작 |

통신판매 신고 사업자 전체는 패션 사업자 전체와 동의어가 아니다. 반대로 패션 브랜드 중에서도 모든 대상이 신고 공개 데이터나 DART에 잡히는 것은 아니다. 그래서 A~F 층위를 합쳐야 "국내 패션 커머스"의 실질적 지도를 만들 수 있다.

## 수집 파이프라인

```text
공식 모수 수집 → 패션 관련성 분류 → 중복·법인 연결 → 공식 웹 근거 보강
                 ↓                         ↓
            보류/미분류 큐             검증 상태 부여
                 ↓                         ↓
              재검토 일정 ← 변경·휴폐업·출처 만료 감지
```

### 1. 모수 수집

- 통신판매사업자: 공정거래위원회 지역별 전체 CSV 또는 공식 API를 수집한다.
- 공시 기업: DART의 공시 대상 법인에서 의류·패션·유통 관련 후보를 수집한다.
- 플랫폼·브랜드: 각 서비스의 공식 판매자/브랜드 목록과 사업자 정보를 후보로 수집한다.

원본 파일은 `data/raw/`에 두되, 출처의 재배포 조건을 확인하기 전에는 저장소에 올리지 않는다.

개인사업자 공개 신고 데이터처럼 개인 식별 가능 정보가 섞일 수 있는 원본은, 재배포 조건과 별개로 데이터 최소화 원칙을 적용한다. 원본은 로컬 제한 경로에 두고 Git에는 메타데이터·집계·검증된 사업 관계만 기록한다.

### 2. 패션 관련성 분류

자동 키워드만으로 패션 여부를 확정하지 않는다. `apparel`, `accessory`, `shoes`, `fashion_beauty`, `outdoor`, `golf`, `resale_fashion` 등 후보 분류를 남기고, 공식 상품·브랜드·서비스 근거로 검증한다.

### 3. 정규화·연결

- 법인명, 상호, 브랜드명, 도메인, 신고번호, DART 고유번호를 가능한 한 분리 기록한다.
- 서로 다른 표기가 같은 대상을 뜻하는지 확정하기 전에는 병합하지 않는다.
- 하나의 회사가 여러 브랜드·쇼핑몰을 운영할 수 있고, 하나의 브랜드가 여러 채널에서 팔릴 수 있다는 관계를 보존한다.

### 4. 검증 상태

| 상태 | 뜻 |
| --- | --- |
| `verified` | 공식 출처가 현재 속성 또는 관계를 직접 뒷받침 |
| `partially_verified` | 대상은 확인됐지만 운영·소유·카테고리 중 일부가 미확인 |
| `candidate` | 수집 모수에 들어왔지만 패션 관련성 또는 중복이 미확정 |
| `inactive_or_historical` | 휴·폐업, 종료, 과거 자료로 보이며 재확인이 필요 |

## 품질 지표

각 수집 배치에는 아래 숫자를 남긴다.

- 원본 행 수
- 중복 제거 후 후보 수
- 패션 관련 후보 수
- `verified` / `partially_verified` / `candidate` 수
- 확인 불가·제외 수와 이유
- 기준일, 사용 출처, 담당 수집 규칙 버전

이 지표가 있어야 나중에 “어디까지 조사했는가”를 감이 아니라 숫자로 설명할 수 있다.
