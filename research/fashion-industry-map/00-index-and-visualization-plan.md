# 패션산업 지도: 자료 운영 기준과 시각화 계획

작성일: 2026-10-26  
목적: 조사 자료가 늘어날수록 중복·추측·복잡함이 커지지 않도록, 무엇을 어디에 기록하고 나중에 어떻게 보여 줄지 정한다.

### 기본 데이터 점검 결과 (2026-10-26)

- 쇼핑몰 252건은 동일 URL 중복이 확인되지 않았다.
- 엔터티 228건과 관계 168건을 대조했을 때, 존재하지 않는 대상을 가리키는 관계는 없었다.
- 여성 전용과 유니섹스·남녀 동시 전개 범위를 분리해 보고 있으며, 여성·유니섹스 브랜드는 현재 76건이다.
- 이 점검은 형식·연결 상태만 확인한 것이다. 각 사이트의 현재 운영 여부와 정보의 최신성은 별도 재확인이 필요하다.

## 2. 불필요하게 늘리지 않을 것

- 같은 쇼핑몰·브랜드를 여러 CSV에 이름만 바꿔 중복 저장하지 않는다. 고유 ID와 관계 데이터로 연결한다.
- `기업이 쇼핑몰을 운영함`을 `모든 브랜드가 그 쇼핑몰에서 판매됨`으로 바꾸어 기록하지 않는다.
- 확인하지 않은 가격대, 고객 연령, 매출, 시장점유율을 추정으로 채우지 않는다.
- “국내 모든 쇼핑몰”처럼 검증할 수 없는 완료 표현을 쓰지 않는다. 수집 범위·확인일·출처를 함께 남긴다.
- 설명 문서는 원리를 설명하고, CSV는 실제 레코드를 담는다. 같은 내용을 문서와 CSV에 반복 복사하지 않는다.

## 4. 시각화는 이렇게 단계적으로 만든다

### 화면 1: 전체 현황 대시보드

가장 먼저 만들 화면이다. 숫자와 필터로 현재 수집 범위를 보여 준다.

```text
[쇼핑몰 수] [기업·브랜드 수] [관계 수] [최근 확인일]

유형 필터 / 고객·상품 카테고리 필터 / 확인일 필터

검색 가능한 목록표
```

### 화면 2: 국내 패션산업 흐름 지도

7개 영역을 흐름으로 보여 준다. 자료가 없는 영역도 “조사 예정”으로 표시해 공백을 숨기지 않는다.

```text
소재·부자재 → 제조·생산 → 기업·브랜드 → 유통·판매 → 소비자
                                  ↓
                         보세·개인 쇼핑몰

                서비스·지원 산업 / 시장·소비자·트렌드
```

### 화면 3: 기업·브랜드·채널 관계도

기업 하나를 선택하면 보유 브랜드와 운영 채널이 보이는 네트워크 또는 트리 화면이다. 실제 판매가 확인된 관계와 단순 운영 관계는 선 색·라벨로 구분한다.

```text
코오롱인더스트리 FnC
 ├─ 코오롱스포츠
 ├─ 럭키슈에뜨
 ├─ 코오롱몰
 └─ 더카트
```

### 화면 4: 경쟁사 비교 화면

DB가 충분해진 뒤에만 만든다. 특정 브랜드·쇼핑몰을 선택하면 판매 채널, 가격대, 카테고리, 프로모션, 신상품·품절 변화를 비교한다.

## 5. HTML 제작 원칙

- 처음에는 외부 DB 서버 없이 CSV·JSON을 읽는 정적 HTML로 시작한다.
- 첫 화면은 `index.html`에 만들었다. 정적 웹 서버나 GitHub Pages에서 열면 원본 CSV의 행 수와 플랫폼 목록을 읽어 갱신하며, 파일을 직접 열 때는 마지막 스냅샷을 보여 준다.
- 모든 수치에는 기준일과 데이터 출처를 보이게 한다.
- 화면의 필터는 데이터에 실제 존재하는 값만 표시한다.
- 관계가 미확인인 경우 빈칸 또는 `미확인`으로 보여 주며 추정하지 않는다.
- 모바일보다 PC에서 표·관계도를 보기 편하게 먼저 설계하고, 이후 반응형으로 보완한다.

## 6. 가장 효율적인 다음 작업 순서

1. 기존 200개 쇼핑몰의 확인일·유형·URL 품질을 유지한다.
2. 주요 패션기업 5~10곳의 기업 → 브랜드 → 자사몰 관계를 공식 근거로 채운다.
3. 대표 브랜드부터 실제 판매 채널을 확인해 `sells_through` 관계를 늘린다.
4. 백화점·아울렛·동대문 도매를 별도 조사한다.
5. 이 데이터로 화면 1(전체 현황)과 화면 2(산업 흐름 지도)를 먼저 만든다.

이 순서는 “자료를 많이 모으는 것”과 “보기 쉬운 결과물을 만드는 것”을 동시에 만족시키기 위한 기준이다.
